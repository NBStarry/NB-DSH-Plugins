# Skills

A read-only sidebar inventory: open **Skills** without selecting or starting a session, search by name or path, inspect each entry's source and instructions, and refresh. Same-name files from different scanned locations remain separate. This is an inventory of recognized files, not a guarantee that a given Agent can invoke them; invocation flags describe skill policy, not access or current tool availability.

The panel scans user roots derived from `DSH_HOME` (default `~/.dsh`) and `DSH_AGENTS_HOME` (default `~/.agents`), plus `.dsh/skills` and `.agents/skills` under the nearest Git project root for each registered workspace (or the workspace itself when no Git ancestor exists). It shows scanned locations and partial-discovery issues. The DSH user root's `.system` child is skipped, matching the official provider. It does **not** discover a provider's explicitly configured custom home or skill directories, bundled/plugin skills, remote providers, unregistered projects, or hidden/inactive preset providers. Consequently it must not be interpreted as every skill installed anywhere.

The official `@deepseek-ai/dsh-skill-filesystem` provider parses directly nested `<name>/SKILL.md` and top-level `<name>.md`, including its normal symlink behavior. Skill file reads are limited to 1 MiB; malformed files, inaccessible roots, and over-limit reads are reported as incomplete. As in the provider, symlinks may point outside a scanned directory. Scanned roots and their symlinks are trusted local user data; this read-only feature does not provide atomic confinement against a hostile same-user process changing paths concurrently. Detail access accepts only an opaque identifier matched to a fresh server-side enumeration, never a client-supplied path. Results are separate observations, not an atomic filesystem snapshot.

The endpoint uses an exact owner-only `connection.fetch` route under `/api`, the connection bridge's authentication and Host/Origin checks, and `private, no-store` responses. It exposes no write action. This package targets DSH 0.2.2-alpha.2 and declares a runtime dependency on the official filesystem provider; installing or upgrading a bundle can execute allowed build scripts and affect all sessions in the profile. Obtain authorization before changing a profile. Desktop IPC transport is unverified.

Run `node --test test.mjs client.test.mjs integration.test.mjs` after installing dependencies in an isolated development environment. Tests use temporary files and a stub connection registration; the official provider integration test uses a filesystem adapter stub. They do not prove real connection authentication or a rendered UI. Those need verification in an authorized DSH environment. No create, edit, delete, install, or enable operation is provided; safe persistent management needs a separately authorized Host service, stale-write protection, and race/symlink defenses.
